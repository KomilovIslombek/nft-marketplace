# Deploying the NFT Marketplace (free tier)

Three free services, each doing one job:

| Part | Where | Why this one |
|---|---|---|
| Frontend (`front/`) | **Netlify** | Static files on a CDN, so pages load instantly even when the API is asleep. Its proxy rewrites let `/api/*` look like part of the same site (explained below). |
| Backend (`back/`) | **Render** (free web service) | Runs a normal long-lived Node/Express process. No code changes needed, unlike serverless platforms. |
| Database | **MongoDB Atlas** (free M0 cluster) | Managed MongoDB, which the app already uses in development. |

```
Browser ──> https://komilov-nft-marketplace.netlify.app/            static pages (Netlify CDN)
        └─> https://komilov-nft-marketplace.netlify.app/api/...     ─proxy─> https://komilov-nft-api-6bjd.onrender.com/api/...
                                                                     └─> MongoDB Atlas
```

**Why the proxy matters.** The login cookie is `httpOnly` and `SameSite=Strict`.
`netlify.app` and `onrender.com` are different sites, so if the page called the
Render URL directly, the cookie would be a third-party cookie. A
`SameSite=Strict` cookie is never sent cross-site, and Safari and Firefox
block third-party cookies anyway, so login would silently fail. Through the
Netlify proxy the browser only ever talks to one domain: the cookie is
first-party, there are no CORS preflights, and the cookie settings stay
strict. `front/assets/js/config.js` uses a relative `/api` in production for
exactly this reason.

**Free-tier trade-off.** Render's free service sleeps after 15 minutes
without traffic and takes up to about a minute to wake up. Netlify's proxy
gives up on a request after roughly 26 seconds. To keep that from
looking broken, `apiFetch()` retries read-only requests while the server wakes
up and shows a "Waking up the server…" note. If you want no wait at all, see
step 6 (optional keep-alive ping).

**Status (2026-11-27): deployed.** Frontend:
<https://komilov-nft-marketplace.netlify.app>. API: Render service
`komilov-nft-api-6bjd`. Database: `nft-marketplace-prod` on the Atlas
cluster. The steps below document how it was set up, and how to redo it.

---

## 0. Before you start

- The code is committed locally. Push it to GitHub first
  (`git push origin main`): Netlify and Render both deploy from the GitHub repo.
- Tests should pass: `cd back && npm test`.

## 1. MongoDB Atlas: database + connection string

1. Sign in at <https://cloud.mongodb.com> (you already have a cluster for
   development; a free M0 cluster is enough).
2. **Use a separate database for production.** The database name goes in the
   connection string, after the host:
   `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/nft-marketplace-prod?retryWrites=true&w=majority&appName=Cluster0`
   That way local experiments never touch the live demo's data.
3. **Database Access** → add a database user just for production (e.g.
   `nft-prod`) with a generated password and the "Read and write to any
   database" role. Keep the password for step 3.
4. **Network Access** → **Add IP Address** → `0.0.0.0/0` ("allow access from
   anywhere"). Render's free tier has no fixed outbound IP, so there is no
   narrower address to allow. The database password is what protects it.

## 2. Seed the production database (from your computer)

The demo creators, NFTs and sale history come from `npm run seed`. Run it once
against the **production** URI:

```powershell
cd back
$env:MONGODB_URI = "mongodb+srv://nft-prod:<password>@cluster0.xxxxx.mongodb.net/nft-marketplace-prod?retryWrites=true&w=majority&appName=Cluster0"
npm run seed
Remove-Item Env:MONGODB_URI
```

- Do **not** set `DEMO_PASSWORD` for this. Without it every demo creator gets a
  random password, so nobody can log in as "Shroomie" on the live site and
  delete the demo NFTs.
- The generated sale history is relative to the moment you seed it: the
  "Last 7 / 30 / 90 days" tabs on Rankings fill up and then empty out as time
  passes. The homepage uses all-time figures, so it always has data. Re-run
  the seed right before you send the link to someone, for example before
  applying for a job. Re-seeding gives the demo NFTs new ids, so old
  `nft.html#id=…` links stop working, but nothing else is affected.

## 3. Render: deploy the API

1. Sign in at <https://render.com> with GitHub.
2. **New → Blueprint** → pick the `nft-marketplace` repository. Render reads
   [`render.yaml`](../render.yaml) and proposes one free web service,
   `komilov-nft-api`.
3. It asks for the values marked `sync: false`:
   - `MONGODB_URI`: the production connection string from step 1
   - `FRONTEND_URL`: leave it as `https://example.netlify.app` for now and fix
     it in step 5 (you don't have the Netlify URL yet)
   - `GOOGLE_CLIENT_ID`: the same client ID as in your local `.env`

   `JWT_SECRET` is generated by Render. Don't copy your local one.
4. **Apply**. The first build takes a few minutes. When it's live, open
   `https://<service-name>.onrender.com/api/health`. It should return
   `{"status":"ok",...}`.
5. Note the exact service URL (top left of the service page). For this
   deployment it is `https://komilov-nft-api-6bjd.onrender.com`, and
   `netlify.toml` points there. On a fresh Blueprint the suffix differs:
   edit the `to = ...` line in [`netlify.toml`](../netlify.toml), commit and
   push. **This matters:** `*.onrender.com` names belong to whoever claims them
   first. The original name `nft-marketplace-api` was already someone else's
   service, so a proxy pointing at it would have sent visitors' requests,
   cookies included, to a stranger's server.

## 4. Netlify: the frontend (already created)

The Netlify project **`komilov-nft-marketplace`** exists, and the frontend is
deployed at **<https://komilov-nft-marketplace.netlify.app>**. That address is
the free subdomain Netlify gives every project; the name was picked on
creation. Build settings come from [`netlify.toml`](../netlify.toml): publish
`front/`, no build command.

The project is linked to the GitHub repository (branch `main`), so every
push redeploys the frontend. To link a fresh project the same way:
**Project configuration → Build & deploy → Continuous deployment → Link
repository** → GitHub → `nft-marketplace`, branch `main`. Leave the build
settings empty: `netlify.toml` provides them.

Once Render is up (step 3), open
`https://komilov-nft-marketplace.netlify.app/api/health`. The API's JSON there
means the proxy works.

## 5. Connect the two

1. **Render → your service → Environment** → set `FRONTEND_URL` to the real
   Netlify URL, `https://komilov-nft-marketplace.netlify.app` (no trailing
   slash; comma-separate if you ever add a custom domain). Save. Render
   redeploys.
2. **Google sign-in:** <https://console.cloud.google.com/apis/credentials> →
   your OAuth client → **Authorized JavaScript origins** → add the Netlify URL.
   Without this, "Sign in with Google" fails on the live site.
3. Check the live site:
   - homepage stats, Top Categories, Top Creators and the spotlight banner load
   - Marketplace search and category filters work
   - Register a test account → you land on Profile → reload → still logged in
     (this proves the cookie survives the proxy) → Log out
   - Rankings → "All time" shows the leaderboard

## 6. Optional: no cold starts

A free uptime monitor (e.g. <https://uptimerobot.com>, HTTP monitor every 5
minutes) pointed at `https://<service-name>.onrender.com/api/health` keeps the
service awake. One always-on service uses about 744 of Render's 750 free
hours a month, so this works for **one** service only.

## 7. Afterwards

- Put the live URL in the README (replace the placeholder in the
  "Live demo" line) and in your portfolio.
- Every push to `main` redeploys both: Render (API) and Netlify (frontend).
  GitHub Actions runs the backend tests on every push too.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Render build OK, but the service exits with `Mongodb connection failed` | Wrong `MONGODB_URI`, or Atlas Network Access doesn't include `0.0.0.0/0`. |
| `/api/health` on the Netlify URL shows Netlify's 404 page | The `to =` host in `netlify.toml` doesn't match the Render URL. |
| The first page load says "Waking up the server…" for ~1 minute | Normal on the free tier after 15 idle minutes (see step 6). |
| Login "works" but reloading logs you out | Calling the Render URL directly instead of `/api`. `config.js` must return `/api` on the live domain. |
| "Sign in with Google" popup errors on the live site | The Netlify URL is missing from the Google client's Authorized JavaScript origins. |
| Rankings "Last 30 days" is empty | The seeded history is older than 30 days. Re-run step 2. |
